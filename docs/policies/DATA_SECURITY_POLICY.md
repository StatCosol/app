# Data Security Policy — StatComPy

**Version:** 1.0
**Effective date:** 8 May 2026
**Owner:** Head of Engineering, StatCo Solutions Pvt. Ltd.
**Review cadence:** Annually, or after any P1 security incident.

This policy describes the technical and organisational measures ("TOMs") StatCo applies to protect the StatComPy platform and the Customer Data it processes. It is intended for Customer security review and audit purposes and aligns with **OWASP ASVS Level 2**, **OWASP Top 10 (2021)**, and the **ISO/IEC 27001:2022 Annex A** control families.

---

## 1. Scope

Applies to:

- The StatComPy backend (NestJS) and frontend (Angular) application code.
- The Azure cloud environment hosting production (resource group `statcompy-rg`, region Central India).
- All StatCo personnel with access to production data or infrastructure.

## 2. Governance

- **Security owner:** Head of Engineering.
- **Risk register** maintained quarterly; reviewed by management.
- **Security training** for all engineers at onboarding and annually thereafter.
- **Vendor/sub-processor review** before onboarding and on contract renewal.

## 3. Identity & access management

- Passwords stored as **bcrypt** hashes (cost ≥ 10).
- **JWT** access tokens (HS256, 15-minute lifetime) and refresh tokens (rotated, hashed at rest).
- **RBAC** roles: `ADMIN`, `CEO`, `CCO`, `CRM`, `AUDITOR`, `PAYROLL`, `CLIENT`, `BRANCH_DESK`, `CONTRACTOR`, `EMPLOYEE`. Enforced by `JwtAuthGuard` + `RolesGuard` on every controller.
- **Tenant scoping** by `client_assignments` (CRM/Auditor) and `users.owner_cco_id` (CCO subordinates).
- **Brute-force protection:**
  - Per-IP via `@nestjs/throttler` (10 logins/min, 5 password resets / 5 min).
  - Per-email lockout in `AuthService` after repeated failures.
- **MFA roadmap:** TOTP for admin roles in next release; Customer can enforce SSO via Azure AD on enterprise tier.
- Cloud admin access (Azure portal, ACR, Postgres) restricted to a named list with Azure AD MFA + Conditional Access.

## 4. Cryptography

- **In transit:** TLS 1.2+ enforced by Azure Container Apps; HSTS `max-age=31536000; includeSubDomains; preload`.
- **At rest:** AES-256 (Azure-managed keys) on PostgreSQL Flexible Server and Container App storage.
- **Secrets:** Stored as Container App secrets; never committed to git; rotated on personnel changes and at least annually.
- **JWT secret:** ≥ 32 bytes, generated by CSPRNG, distinct from refresh-secret.

## 5. Application security

- All inputs validated server-side via `class-validator` DTOs (`whitelist + forbidNonWhitelisted + transform`).
- All DB access via TypeORM **parameterised queries**; no string-concatenated SQL.
- Output: `helmet` enforced headers — CSP `default-src 'self'`, `frame-ancestors 'none'`, `referrer-policy: no-referrer`, `cross-origin-resource-policy: same-site`.
- Static `/uploads/*` is gated by JWT (Bearer header only); only `/uploads/logos/*` and `/uploads/news/*` are public.
- Swagger UI disabled in production (`NODE_ENV=production`).
- CORS allow-list driven by `CORS_ORIGINS` env in production; permissive only in dev.
- File upload limits: 2 MB JSON body, server-side MIME / extension allow-list, virus-scan hook reserved (TBD).
- No use of `eval`, `child_process` with user input, or unsigned dynamic code paths.

## 6. Logging, monitoring, audit

- **Application logs:** structured JSON via `nestjs-pino`, shipped to Azure Log Analytics by Container Apps.
- **Audit trails:**
  - `user_login_logs` — every authentication attempt (success/failure, IP, UA).
  - `payroll_config_audit` — admin-initiated configuration mutations.
  - Soft-delete records keep `created_by` / `deleted_by` for forensic trace.
- **Health endpoint:** `/api/v1/health` polled by Container App probes.
- **Alerts (configured / planned):** 5xx rate, p95 latency, container restart count, DB connection failures, login-failure spike per IP.

## 7. Vulnerability management

- `npm audit --audit-level=moderate` runs on every CI build; build fails on new moderate+ findings.
- Quarterly dependency review; Dependabot/Renovate planned.
- External **VAPT** before each major release; closure report retained.
- Coordinated disclosure inbox: **security@statcosol.com**.

## 8. Backups & disaster recovery

- See `BACKUP_AND_DR_POLICY.md` for full RPO/RTO and drill schedule.
- Summary: Azure PG point-in-time backups, 35-day retention; encrypted; daily restorability check.

## 9. Change management

- All production changes via git PR + code review.
- Production deploys via tagged ACR images (`v<YYMMHHMMsales>`) with revision suffix; previous revision retained for instant rollback.
- Database migrations versioned in `backend/migrations/`; idempotent (`IF NOT EXISTS`); applied via reviewed runner script.

## 10. Personnel security

- Background verification at hiring.
- NDAs signed by all personnel before access.
- Joiner / mover / leaver checklist; access revoked within 24 hours of separation.
- Production access strictly need-to-know; reviewed quarterly.

## 11. Endpoint security (developer & admin)

- Full-disk encryption mandatory.
- Reputable EDR/AV.
- Auto-update enabled; OS patched within 14 days of vendor release for critical CVEs.

## 12. Incident response

- See `INCIDENT_RESPONSE_POLICY.md`.
- Customer notification within 72 hours of confirmed personal-data breach (DPDP Act / GDPR-aligned).

## 13. Compliance with this policy

Violations by personnel are subject to disciplinary action up to and including termination. Customers experiencing or suspecting a security issue should contact **security@statcosol.com**.
